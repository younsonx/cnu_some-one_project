# 관리자 대시보드 설계

## 1. 접근 제어

`/admin`은 요청마다 사용자 신원을 확인해야 하므로 동적 서버 페이지로 렌더링됩니다.

1. Sign in with ChatGPT를 통해 로그인
2. 플랫폼이 전달한 사용자 이메일을 서버에서 확인
3. `ADMIN_EMAIL` 환경 변수의 허용 이메일과 비교
4. 일치하는 경우에만 D1 전체 집계 실행

로그인은 사용자를 식별하는 인증이고, 이메일 허용 목록 비교는 관리자 권한을 판단하는 인가입니다.

## 2. 대시보드 구성

### 전체 현황

- 실제 참가자 수와 여성·남성 인원
- 전체 하트와 색상별 개수
- 최종 상호 선택 수

### 단계별 제출률

- 1차 기대 인원: 여성 참가자 수
- 2차 기대 인원: 남성 참가자 수
- 3차 기대 인원: 전체 참가자 수
- 선택 기록의 고유 발신자 수를 완료 인원으로 집계

### 전체 선택 기록과 개인별 결과

선택 테이블을 참가자 테이블에 두 번 JOIN해 발신자와 수신자의 닉네임을 조회합니다. 이후 `recipientId` 기준으로 분류해 참가자마다 1·2·3차 수신 결과를 표시합니다.

### 최종 상호 선택

3차 빨간 하트 중 `A → B`와 `B → A`가 모두 존재하는 경우를 찾습니다. 한 쌍이 두 번 표시되지 않도록 여성 발신 기록을 기준으로 결과를 생성합니다.

## 3. 테스트 데이터 초기화

관리자 화면 하단의 초기화 기능은 다음 보호 장치를 사용합니다.

- POST 요청만 허용
- 로그인 사용자 및 관리자 이메일 재검증
- 요청 Origin 검사
- 숨겨진 확인값 검사
- 선택 기록을 먼저 삭제한 뒤 실제 참가자 프로필 삭제

초기화 후 기존 참가자 브라우저의 토큰은 더 이상 유효하지 않으며 다시 프로필을 만들어야 합니다.

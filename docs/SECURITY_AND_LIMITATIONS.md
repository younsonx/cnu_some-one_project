# 보안, 개인정보와 현재 한계

## 적용한 보호 방식

- 비밀번호를 무작위 salt와 PBKDF2-SHA256 해시로 저장
- 참가자 ID와 별도로 긴 임의 세션 토큰 사용
- 서버에서 토큰에 연결된 참가자를 다시 조회
- 화면 상태를 신뢰하지 않고 단계·성별·상대를 서버에서 재검증
- 개인 결과는 현재 참가자가 수신자인 기록만 반환
- 관리자 페이지는 로그인과 이메일 허용 검사를 모두 통과해야 접근 가능
- 관리자 초기화 요청은 권한·Origin·확인값 검사 수행
- 관리자 이메일은 Git에 저장하지 않고 배포 환경 변수로 관리
- `.dev.vars`, 빌드 파일, 의존성 디렉터리를 `.gitignore`로 제외

## MVP 한계

### 참가자 인증

참가자는 닉네임과 비밀번호로 다시 로그인할 수 있습니다. 브라우저에는 세션 토큰만 남고 평문 비밀번호는 저장하지 않습니다. 현재는 사용자가 직접 수행하는 비밀번호 재설정 기능은 제공하지 않습니다.

### 전역 행사 단계와 결과 공개

`event_state`가 행사 전체 단계를 저장합니다. 서버는 1차 여성 전원, 2차 남성 전원, 3차 전체 참가자 제출을 확인해 자동 전환하고, 완료되지 않은 단계의 선택과 결과 조회를 차단합니다.

### 여러 행사 분리

현재 데이터는 하나의 행사 공간을 기준으로 합니다. 여러 행사를 운영하려면 참가자와 선택에 `event_id`를 추가하고 행사 코드로 입장시키는 구조가 필요합니다.

### 개인정보 운영

실행 전 수집 정보와 목적, 결과 열람 기간, 자동 삭제 시점, 운영자 권한 회수와 세션 토큰 재발급 절차를 정의해야 합니다.

## 다음 개발 우선순위

3. 행사별 데이터 분리
4. 재입장 코드 또는 휴대폰 인증
5. 실시간 현황 갱신
6. 행사 종료 후 자동 삭제 및 통계 내보내기
